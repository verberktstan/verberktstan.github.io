clj-insim

2021–2026 · A Clojure client for Live For Speed's InSim binary protocol, built on core.async.

View on GitHub

Live For Speed is a racing simulator that exposes a binary TCP/UDP interface called InSim. External programs can use it to read race state, react to events and draw buttons on the driver's screen. clj-insim lets you do all of that from a Clojure REPL.

What it does

You start a client and give it a dispatch function. Every incoming packet arrives as plain Clojure data.

(let [client (client/start)]
  (client/go client (fn [_ packet] (println packet)))
  client)

The library ships with example clients for race safety monitoring, live scoring and on-screen buttons. Each one is a few dozen lines of data transformation.

The interesting parts

  • Codecs as data. Every packet type is described once, as a declarative spec. That spec drives both parsing and writing, so encoding and decoding can't drift apart.
  • Async architecture. Version 0.3 was a full rewrite around core.async channels. Reading, writing and dispatching are decoupled, so a slow handler never blocks the socket.
  • Long-lived. I started it in 2021 and still maintain it, with 120+ commits, CI and tagged releases.

What I learned

Binary protocols reward rigour. Byte order, padding and fixed-width strings all have to be right. Once the codec layer was trustworthy, everything above it became pleasantly boring: just maps going in and maps coming out.
